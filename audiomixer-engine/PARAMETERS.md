# WS parameter reference

The full, authoritative, machine-readable version of everything in this document is the
`amixer/{mixerId}/init` message (`src/schema.rs`) — sent once to every new WebSocket connection
immediately on open, and re-broadcast to every connected client whenever the mixer's own topology
changes (a track/bus/master CREATE or DELETE). This file is a human-readable rendering of that same
schema, generated by connecting to a live instance and reading its own `init` message back
(2026-09-18, re-checked against `path_prefix`/`collections`/`kind_labels` on 2026-09-19) — if the two
ever disagree, `src/schema.rs` is right and this file is stale; regenerate it from a live `init`
message rather than hand-editing around the difference.

Built for a "command proxy" use case: a separate control surface hosting UI composed from several
different apps' own commands/information at once, not just this one — such a proxy can't have this
app's own param names/types/ranges hard-coded into it, so this (and the live `init` message it's
generated from) is what it discovers this mixer's shape from instead.

## Protocol basics

One WebSocket, `ws://<host>:<ws_port>/amixer/api/socket`. Every message either direction is
`{"path": "<path>", "value": <json>}`, except a client's own outgoing commands, which also carry an
`"op"`:

```json
{"op": "PUT", "path": "amixer/0/channel/3/fader", "value": -6.0}
{"op": "CREATE", "path": "amixer/0/channel", "value": {"id": 7, "label": "New Track", "channels": 2}}
{"op": "DELETE", "path": "amixer/0/channel/7"}
```

- **`PUT`** — set one param, at `amixer/{mixerId}/{kind}/{id}/{param}` (a track/master's own
  processing-chain slots address one level deeper: `.../stage/{index}`). A structured param
  (`sends`, `adm-objects`, `input-patch`, ...) always replaces the *whole* value in one PUT — there
  is no partial/incremental update for an array-shaped param anywhere in this protocol. A rejected
  PUT (wrong shape, out-of-range index, unknown path) is a silent no-op from the wire's own
  perspective — it logs server-side (`tracing::warn!`) but sends no error envelope back; this
  protocol has no request/response correlation id to hang one off of. Every successful `PUT` is
  echoed back over the same broadcast channel every other client also sees (not just the sender).
- **`CREATE`** / **`DELETE`** — runtime topology changes for `channel` (track) / `sum` (bus) /
  `master` only — the NMOS-facing input/output grid is a fixed, config-time-only set of slots (see
  `PICKOFFS.md`). Triggers an `amixer/{mixerId}/init` re-broadcast (below) in addition to the
  existing `channel-list`/`sum-list`/`master-list` re-publish.
- **`WATCH`** — accepted, currently a no-op (this app always broadcasts every change to every
  connected client rather than scoping pushes to what a client actually asked to watch).
- No `GET` op exists. A client learns a resource's *structural* params (`chain`, `adm-objects`,
  `sends`, `input-patch`, the three `*-list`s, the input/output grid lists) from the periodic meter
  broadcast tick (`run_meter_broadcaster`, `meter_hz` times/second) or from the `init` snapshot on
  connect; `gain`/`fader`/`mute`/`solo`/`lfe-trim` ride *only* their own PUT echo, never the
  periodic tick — which is exactly why `init` exists: without it, a client that connects and never
  happens to see one of those PUTs has no way to learn the current value at all.

## `init` / re-init

Sent as `{"path": "amixer/{mixerId}/init", "value": {...}}`:

```jsonc
{
  "mixer_id": 0,
  // The three fields below exist for one consumer: a generic aggregating proxy (mxl-proxy) whose
  // UI client renders *any* backend's schema, not just this app's -- see each field's own note.
  "path_prefix": "amixer/0",
  "collections": { "channel": "channels", "sum": "sums", "master": "masters", "input": "input_grid", "output": "output_grid" },
  "kind_labels": { "channel": "Channels", "sum": "Buses", "master": "Masters", "input": "Input grid", "output": "Output grid" },
  "schema": {
    "layouts": { /* every named ChannelLayout -- see "Layouts and roles" below */ },
    "params":  { /* per resource kind -- see the tables below */ }
  },
  "topology": {
    "channels": [ /* every track, id/label/channels/layout + all its current live values */ ],
    "sums": [ /* every bus */ ],
    "masters": [ /* every master */ ],
    "input_grid": [ /* every input-grid entry */ ],
    "output_grid": [ /* every output-grid entry */ ]
  }
}
```

`schema` is static for the life of the process (it doesn't depend on which tracks/buses exist, only
on this app's own fixed capabilities) — `topology` is the actual current state, in the same
per-field JSON shape the ordinary broadcast stream already uses for each field (so a proxy that
learned a resource's shape from `init` recognizes that resource's own fields again later on the
regular `{"path","value"}` stream — one wire shape, not two to keep in sync).

- **`path_prefix`** — what a proxy must splice between the mixer id and a `<kind>/<id>/<param>`
  triple to get this app's own real WS path (`"amixer/0"` here, since every real path looks like
  `amixer/0/channel/3/fader`). A backend with no such quirk (e.g. a REST-polled app whose paths have
  no prefix at all) states `""` instead of omitting the field, so a generic client never needs to
  guess whether the field is merely absent-and-empty vs. genuinely not applicable.
- **`collections`** — maps each `schema.params` kind to its own `topology` array's key, since this
  app's own convention is singular-kind/plural-collection (`channel` params describe the `channels`
  array) — a backend where kind name already equals collection key doesn't need to state this at
  all; a generic client falls back to identity when the field is absent.
- **`kind_labels`** — a plain display label per kind (`"sum"` → `"Buses"`), purely cosmetic, never
  used for addressing. Also optional; a generic client auto-humanizes the bare kind name
  (`"input_grid"` → `"Input grid"`) when absent.

Re-sent to **every** connected client on any track/bus/master CREATE or DELETE. Not currently
re-sent for a registry-discovered input-grid entry appearing/disappearing (`nmos/discovery.rs`) —
that's a real, live topology change too, just not wired into this yet.

## Layouts and roles

`schema.layouts` — one entry per named `ChannelLayout` (`Discrete`, the arbitrary-count/no-roles
case, is deliberately excluded — nothing to describe beyond a bare channel count). Channel *order*
follows this app's own WAV/file-based convention, not ITU/Dolby ordering (`layout.rs`'s own doc
comment). `azimuth_deg`/`elevation_deg` are `null` for a role with no real BS.2051 position (`M`,
`LFE`) — a real spatial panner never pans an object directly to a dedicated LFE channel, and a
bare mono bed has no defined bed position to begin with.

| Layout | Channels | Roles (in order) |
|---|---|---|
| `mono` | 1 | M |
| `stereo` | 2 | L(30°) R(-30°) |
| `quad` | 4 | L(30°) R(-30°) Ls(110°) Rs(-110°) |
| `surround5_1` | 6 | L(30°) R(-30°) C(0°) LFE Ls(110°) Rs(-110°) |
| `surround7_1` | 8 | L(30°) R(-30°) C(0°) LFE Lss(90°) Rss(-90°) Lrs(135°) Rrs(-135°) |
| `surround5_1_4` | 10 | L(30°) R(-30°) C(0°) LFE Ls(110°) Rs(-110°) Ltf(30°,+30°) Rtf(-30°,+30°) Ltb(110°,+30°) Rtb(-110°,+30°) |

Each role also carries its real ADM `speakerLabel` form (e.g. `L` → `RC_L`, `LFE` → `RC_LFE`) in
the live `init` message, for a proxy that wants to cross-reference against exported Serial ADM XML
(`GET /adm.xml`, `adm.rs`) — omitted from the table above for space.

## Params by resource kind

`type` is one of `float` / `bool` / `string` / `array`. `readonly` means the engine writes it (a
meter, a chain snapshot, the live `pan_object` classification) — PUTting it is accepted by the
protocol but has no effect. An array param's own `item` shape is noted where it isn't just a plain
scalar.

### `channel` (a track — `amixer/{mixerId}/channel/{id}/{param}`)

| Param | Type | Unit/Range | R/W | Notes |
|---|---|---|---|---|
| `gain` | float | dB, -20..20, default 0 | RW | |
| `fader` | float | dB, -128..12, default 0 | RW | |
| `lfe-trim` | float | dB, -20..12, default 0 | RW | Only meaningful when this track's own `layout` has an `Lfe`/`LFE` role — inert otherwise, applied on top of `gain`. |
| `mute` | bool | default false | RW | |
| `solo` | bool | default false | RW | |
| `sends` | array | default `[]` | RW | One entry per bus this track feeds — see **Send shape** below. Full-array replace only. |
| `adm-objects` | array | length == this track's own channel count, always | RW | One per-channel ADM object position, always present on every track now (not just "ADM tracks") — see **AdmObject shape** below. Whether it actually drives the mix anywhere depends on `sends[].pan_mode`. |
| `chain` | array | — | RO | This track's own ordered DSP stages. Self-describing `{index, kind, params}` per entry (`kind` ∈ `filter`\|`eq`\|`dynamics`\|`phase`\|`delay`) — fixed at construction, no live reorder. |
| `input-patch` | array | length == this track's own channel count | RW | One entry per channel, exclusive (one source per channel) — see **Patch entry shape** below. |
| `peakmeter` | array | dBFS, or `null` for silence | RO | Post-fader. |
| `input-meter` | array | dBFS, or `null` | RO | Pre-gain, at the input-patch pickoff point. |
| `compensation-delay-ms` | float | ms | RO | Always `0` today — no stage reports nonzero latency yet. |

### `sum` (a bus — `amixer/{mixerId}/sum/{id}/{param}`)

A bus is a pure summer: no gain/fader/mute/chain of its own.

| Param | Type | Unit/Range | R/W | Notes |
|---|---|---|---|---|
| `input-patch` | array | — | RW | *Summing* (unlike a track's own exclusive `input-patch`) — any number of sources may land on one channel, added together. |
| `master-sends` | array | — | RW | Same **Send shape** as a channel's own `sends`, minus `pickoff` (no fader stage to tap pre/post of). |
| `peakmeter` | array | dBFS, or `null` | RO | |
| `input-meter` | array | dBFS, or `null` | RO | |

### `master` (`amixer/{mixerId}/master/{id}/{param}`)

| Param | Type | Unit/Range | R/W | Notes |
|---|---|---|---|---|
| `fader` | float | dB, -128..12, default 0 | RW | |
| `mute` | bool | default false | RW | |
| `chain` | array | — | RO | Same shape as `channel.chain`. |
| `master-sends` | array | — | RW | Same **Send shape** as `channel.sends`. |
| `input-patch` | array | — | RW | Summing, same as `sum.input-patch`. |
| `peakmeter` | array | dBFS, or `null` | RO | |
| `input-meter` | array | dBFS, or `null` | RO | |
| `compensation-delay-ms` | float | ms | RO | |

### `input` (an input-grid entry — `amixer/{mixerId}/input/{id}/{param}`)

Fixed set of slots at process startup (`PICKOFFS.md`) — no CREATE/DELETE, but see
`SESSION-2026-09-17-GRID-CRUD-AVAILABILITY-DESIGN.md` for the live-subscription story (IS-05

receives from, independent of this WS protocol).

| Param | Type | Unit/Range | R/W | Notes |
|---|---|---|---|---|
| `label` | string | — | RW | This entry's own block-level name — live-renamable (2026-09-18). |
| `channel_labels` | array of string | — | RO | This entry's own per-channel identity within the whole input grid's *one shared* running numbering (`"Grid In 01"`, `"Grid In 02"`, ...) — contiguous and 1-based across every entry, static config-authored or runtime registry-discovered alike. |
| `peakmeter` | array | dBFS, or `null` | RO | |

| Param | Type | Unit/Range | R/W | Notes |
|---|---|---|---|---|
| `label` | string | — | RW | |

| `peakmeter` | array | dBFS, or `null` | RO | |

## Shared shapes

### Send shape (`channel.sends` / `sum.master-sends` / `master.master-sends`)

```jsonc
{
  "bus_id": 1,               // int -- which bus/master this send targets
  "on": true,                // bool
  "level_db": 0.0,           // float, dB, -60..12 -- 0dB == a plain unity bus assignment
  "pickoff": "post_fader",   // "pre_fader" | "post_fader" -- channel sends only, absent on master-sends
  "pan_mode": "auto",        // "auto" | "adm" | "route" -- see mixer::SendPanMode; exactly one drives the mix
  "pan_object": "count_only",// READONLY -- the live PanObject::classify() result, meaningful only when pan_mode=="auto"
  "rotation_deg": 0.0,       // float, deg -- meaning depends on pan_object (Rigid: rotation offset; PanPot: absolute azimuth; Balance: -30..30 L/R span)
  "elevation_deg": 0.0,      // float, deg
  "route": null              // null | bool[track_channels][bus_channels] -- only applied when pan_mode=="route"; kept (not cleared) across a mode switch
}
```

`pan_mode` picks exactly one of three mix paths, per send, independent of every other send on the
same track (`mixer.rs`'s engine dispatch, a single `match`, never more than one applies):

- **`auto`** — `PanObject::classify(track.layout, bus.layout)` decides: a real downmix matrix, the
  classic constant-power PanPot law (Mono→Stereo), classic console Balance (Stereo→Stereo), or
  N-point rigid-array VBAP (a named bed into a compatible named bed) — `pan_object` reports which.
- **`adm`** — this track's own live per-channel `adm-objects` position drives real VBAP panning for
  *this* bus specifically. Works even when the bus has no named `layout` at all (an unlabeled,
  evenly-spaced N-point ring — 2026-09-18) — a real bus-agnostic fallback, not silence.
- **`route`** — the `route` matrix, a plain unity-gain crosspoint (patch-cable-style), for when a
  bus's own channels genuinely aren't a ring to pan across at all (e.g. scattered/non-adjacent
  monitor feeds).

### AdmObject shape (`channel.adm-objects`, one entry per channel)

```jsonc
{
  "name": "Track 3 ch2",     // string
  "gain_db": 0.0,            // float, dB
  "position": { "azimuth": 0.0, "elevation": 0.0, "distance": 1.0 },  // deg, deg, 1.0 == reference distance
  "width": 0.0, "height": 0.0, "depth": 0.0   // float, 0..1 each -- BS.2076 object extent; captured for S-ADM export, no mix effect yet
}
```

### Patch entry shape (`*.input-patch` / `output.patch`)

`null` (unpatched) or:

```jsonc
{ "source": "input:<gridEntryId>" | "track-out:<id>" | "bus-out:<id>" | "master-out:<id>", "channel": 0 }
```

## Not covered by this schema

- Per-stage (`chain[i].params`) field-level shape — varies by `kind`, already self-describing via
  the `{index, kind, params}` envelope every `chain` entry already carries; a proxy that knows
  `dsp::StageKind`'s handful of variants and their own field names doesn't need a separate schema
  entry for this.
- The mixer-level runtime-editable `downmix` coefficient tables (`amixer/{mixerId}/downmix/{src}/{dst}`)
  — a real gap, not yet in `init`, lower priority than the per-resource param schema above.
- Serial ADM XML export/import (`GET /adm.xml`, plain HTTP, not this WebSocket protocol at all —
  `adm.rs`).
